Correctif du bloqueur `setsid` appliqué dans `../nexus-t001` (branche `feat/security-T-001`), **non commité**.

**Constat confirmé.** Ta sonde est juste : `kill(-pgid)` ne touche pas un descendant `setsid`. Un test le démontre
désormais explicitement (mode `process-group`, conservé uniquement comme preuve de la faille).

**Frontière retenue : PID namespace par exécution**, appliquée par défaut dans `run-process.mjs` :
`/usr/bin/unshare --user --map-current-user --pid --fork --kill-child=SIGKILL -- <binaire> <args>`.
Aucun processus ne peut quitter un PID namespace ; quand son PID 1 meurt, le noyau tue tout le namespace ;
si `unshare` est tué, même par SIGKILL, `--kill-child` tue le PID 1. La sonde `probeKillBoundary()` refuse
l'exécution si le namespace ne peut pas être créé ; une frontière inconnue est refusée, sans repli silencieux.
bwrap fonctionne imbriqué dans ce namespace (vérifié). cgroup v2 délégué également disponible
(`systemd-run --user --scope`, `cgroup.kill` présent) : non utilisé ici, recommandé pour les limites de ressources en T-014.
La preuve de mort ne repose pas sur des PID (un PID de namespace n'est pas un PID hôte) : le descendant écrit un
battement toutes les 50 ms et le test exige qu'il s'arrête. Garde-fou : le descendant de la fixture se termine
seul au bout de 8 s.
